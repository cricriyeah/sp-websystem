### 2. Defectos de manejo de excepciones y tipos (posible caída no controlada)
* **`backend/apps/bookings/cupo/apartado.py:112-119`**:
  ```python
  try:
      fecha_salida = date.fromisoformat(fecha_val) if isinstance(fecha_val, str) else fecha_val
  except (ValueError, TypeError):
      continue
  if desde <= fecha_salida <= hasta:
      personas = salida.get('personas')
      if personas is not None:
          grupos_por_fecha[fecha_salida].append(int(personas))
  ```
  - Si un elemento en `apartado_demanda['salidas']` contiene un `fecha_val` no-string (p. ej. `int`, `bool`, etc.), la condición ternaria asigna `fecha_salida = fecha_val` sin llamar a `fromisoformat`. Por tanto, **no lanza excepción dentro del bloque `try`**, y en la línea 116 (`desde <= fecha_salida <= hasta`) Python arroja un `TypeError` no capturado (`'<=' not supported between 'date' and 'int'`), tumbando la petición.
  - De igual forma, si `personas` en la línea 119 tiene un valor no numérico en el JSON (p. ej. `"dos"`), `int(personas)` lanza `ValueError` fuera del `try/except`.

### 3. Contradicción con el spec, consultas duplicadas y código muerto en `CupoDisponibleView`
* **`backend/apps/bookings/views.py:86-96`**:
  - **Inconsistencia de criterio con el spec §4.2**: El spec indica:
    > *«`obtener_contexto_rango` y la cifra `ocupadas` de `/api/cupo/`: mismo criterio, con las mismas consultas agrupadas...»*.
    Sin embargo, `CupoDisponibleView` calcula `ocupadas` filtrando únicamente `Reserva.objects.filter(fecha=fecha, estado__in=ESTADOS_QUE_OCUPAN_CUPO)`. A diferencia de `obtener_contexto_cupo` y `obtener_contexto_rango`, **ignora `salidas__isnull=True` y las filas de `ReservaSalida`**, discrepando de las plazas reales que evalúa el motor.
  - **Consulta duplicada innecesaria**: En la línea 87, `evaluar_cupo` ya ejecuta `obtener_contexto_cupo`, que consulta `demanda_apartada_del_dia`. En la línea 96, la vista vuelve a ejecutar `demanda_apartada_del_dia` haciendo una segunda consulta idéntica a la base de datos para la misma petición.
  - **Código muerto / supuesto falso (líneas 92-93)**:
    ```python
    if excluir_pk is not None:
        ocupadas_qs = ocupadas_qs.exclude(pk=excluir_pk)
    ```
    `_resolver_excluir_pk_apartado` devuelve únicamente una reserva con estado `PENDIENTE_PAGO`. La consulta `ocupadas_qs` filtra por `estado__in=ESTADOS_QUE_OCUPAN_CUPO` (`pagada`, `asignada`, `completada`). La reserva `excluir_pk` jamás puede estar en `ocupadas_qs`, por lo que este `.exclude()` es completamente inocuo y no excluye nada (el apartado se descuenta solo por la suma en `demanda_apartada_del_dia`).
